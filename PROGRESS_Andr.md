## Цель
Приложение для Android, которое **только показывает** семейное дерево из файла `.famtree` — то же, что режим «Просмотр» на ПК. Размещение карточек, линий, флагов и полос пола — **точь-в-точь как на ПК**.

## Что делаем / что НЕ делаем
- Делаем: открыть `.famtree`, схема с pan/pinch-zoom, «По размеру», поиск с перелётом камеры и подсветкой, большое окно человека (фото, данные, переход по родителям/партнёрам/детям), светлая и тёмная тема, 7 языков интерфейса.
- НЕ делаем: редактор, режим «Список», экспорт PNG/PDF, сохранение и автосохранение (файл **никогда не пишется**), ассоциация расширения, установщик, своя шапка окна (`chrome.rs`).

## Решения
Все решения подтверждены пользователем (сессия A2).
- **Архитектура: общее ядро на Rust + egui на Android** (вариант (а) из п. 20 основного PROGRESS). Причина: «точь-в-точь» проще и надёжнее всего получить, если запускать **тот же** код. `layout.rs` (2121 строка, самая сложная часть, вся логика «песочных часов» и шин) зависит только от `model.rs`; `view.rs` + `flags.rs` (флаги рисуются кодом, 197 штук) + `theme.rs` рисуют карточки. Порт на Kotlin/Compose = переписать ~4500 строк и потом вечно синхронизировать две раскладки.
  - Альтернатива (б): Kotlin/Compose, раскладку тянуть через JNI из того же `layout.rs`, а карточки и флаги переписать. Выбирать, только если egui на Android окажется неудобным (клавиатура, жесты) — см. риски.
- **Как подключить код:** отдельный крейт `android/` (cdylib), который подключает файлы десктопа через `#[path = "../src/….rs"] mod …;` (`model, container, media, layout, flags, countries, i18n, theme, view, person_window, search`). Десктоп не трогаем. Если окажется, что модули тянут друг друга (`view` → `app` и т. п.), — разделять на `famtree-core` (lib) + два бинарника, это уже правка десктопа (записать в журнал).
- **Сборка:** GitHub Actions (`ubuntu-latest`, `cargo-ndk` или `cargo-apk`/`xbuild` — выбрать на шаге 1), артефакт — `.apk` (debug, потом подписанный release в GitHub Releases). minSdk 29 (Android 10, выбор пользователя), цели `arm64-v8a` (+ `x86_64` для эмулятора по желанию).
- **Как файл попадает на телефон:** системный выбор файла (Storage Access Framework, `ACTION_OPEN_DOCUMENT`) + открытие `.famtree` из файлового менеджера/«Поделиться». SAF отдаёт `content://`, а не путь → файл копируется в кеш приложения, дальше читается как обычный путь через `container::load`. Последний открытый файл запоминается.
- Формат файла не меняем (`FORMAT_VERSION` = 1), старые и новые `.famtree` читаются.

## Риски (проверить в первую очередь)
1. **Детерминизм раскладки.** В `layout.rs` много `HashMap`/`HashSet`; если где-то порядок обхода влияет на результат, на телефоне схема может отличаться от ПК (и даже от запуска к запуску). Нужен golden-тест: координаты `compute()` для тестовых деревьев (`demo.rs`) сравнивать с эталоном; при расхождении заменять на `BTreeMap`/сортировку.
2. **Экранная клавиатура для поиска** в egui 0.29 на Android: может не открываться сама — тогда вызывать через JNI (`InputMethodManager`) или тонкий Kotlin-слой.
3. **Жесты:** pinch-zoom и pan из egui (`multi_touch`) — проверить плавность на большом дереве; клик по карточке не должен срабатывать после перетаскивания.
4. **Память:** кэш текстур на ПК ≤300 миниатюр, на телефоне, скорее всего, нужно ~100 (проверить). `MediaStore::get` открывает архив на каждую миниатюру — на телефоне заметнее, кэшировать `ZipArchive`.
5. **Шрифты:** Segoe UI нет; нужны кириллица/латиница (встроенные шрифты egui) и CJK для китайского (`/system/fonts/NotoSansCJK*`, путь проверить).
6. **Язык интерфейса:** `i18n::detect_system` на не-Windows читает `LANG` — на Android пусто. Определять через JNI (`Locale`) или `ndk`-конфигурацию.
7. **Окно человека** (`egui::Window`) на телефоне неудобно — делать во весь экран с кнопкой «Назад».
8. Системная кнопка/жест «Назад»: закрывать окно человека, потом выходить.

## Заметки по A3a (для следующей сессии)
- Общие файлы подключены через `#[path = "../../src/…"]`: `i18n.rs`, `model.rs`, `container.rs` (десктоп не менялся, кроме новых строк в `i18n::TABLE`). Лишних зависимостей они не требуют: serde, serde_json (preserve_order), zip (deflate); egui им не нужен.
- `android/src/source.rs` (JNI, крейт `jni 0.21`): `find_file` → копирует файл из интента (`getIntent().getData()` → `ContentResolver.openFileDescriptor` → `detachFd`) в `<internal_data_path>/incoming.famtree`; имя берётся из `_display_name`; иначе — `last.famtree` + `last_name.txt`. `commit` переименовывает входящий в `last.famtree` только после успешной проверки `container::load`; битый файл удаляется (`discard`) и **не затирает** прошлый удачный. Дерево после коммита загружается второй раз уже из `last.famtree` (MediaStore хранит путь).
- Загрузка идёт в фоновом потоке, UI показывает спиннер. Фото пока не используются (`_store`).
- Манифест (`android/Cargo.toml`): MAIN/LAUNCHER + VIEW-фильтры (content/file, `host="*"`, `*/*`, `pathPattern .*\.famtree`) и второй VIEW-фильтр для `application/octet-stream` и `application/zip` (файловые менеджеры часто прячут расширение). Минус второго фильтра: FamTree будет предлагаться и для обычных zip.
- Известные ограничения: если приложение уже открыто и из менеджера открывают другой файл, интент в Rust не приходит (нет `onNewIntent`) — решится вместе с Java-прослойкой (A3b); при перезапуске из «недавних» тот же интент копируется заново; верхний отступ 48 px временный (A7).
- Риски CI: имена ключей `intent_filter`/`data` в метаданных `cargo-apk` (по памяти и по `ndk-build::IntentFilterData`: `scheme, host, port, path, path_pattern, path_prefix, mime_type`); API `jni 0.21` (`JValue::Object(&…)`, `JString::from`, `AttachGuard`); `AndroidApp::vm_as_ptr/activity_as_ptr` (есть в android-activity 0.6).
- Проверить на телефоне: (1) запуск с иконки — «Откройте файл…»; (2) файловый менеджер → `.famtree` → «Открыть с помощью» → FamTree → «Файл: … / Людей в дереве: N»; (3) закрыть и запустить с иконки — открывается последний файл; (4) открыть не-`.famtree` zip — красная ошибка, прошлый файл остаётся.

## Заметки по A3b (для следующей сессии)
- `android/java/io/github/john3sobieski/famtree/FamActivity.java` — `extends NativeActivity`: `pickFile()` (ACTION_OPEN_DOCUMENT, `*/*`), `onActivityResult` и `onNewIntent` отдают URI (строкой) в Rust через `nativeUri(String)`. Метод привязывается из Rust при старте через `RegisterNatives` (`source::register_natives`, `android_main`), а не по имени символа и не через `System.loadLibrary` (NativeActivity не регистрирует свою .so для JNI-поиска по имени). Если привязка не удалась — в логе `register_natives failed`, кнопка «Открыть» ничего не вернёт.
- Rust: `PICKED` (глобальная строка) + `CTX` (будит UI). Загрузка по URI: `source::find_file(app, Some(uri))` → `Uri.parse` → `copy_uri`. Одна загрузка за раз (иначе два потока пишут один `incoming.famtree`).
- Манифест (`android/Cargo.toml`): `application.has_code = true`, `activity.name = "io.github.john3sobieski.famtree.FamActivity"`, `launch_mode = "singleTask"` (нужен для `onNewIntent`).
- CI (`android.yml`, шаг «Add Java layer»): `javac --release 11` → `d8` → `classes.dex` добавляется в APK питоном (старая подпись `META-INF/` отбрасывается) → `zipalign -p 4` → `apksigner sign` временным ключом → `android/dist/FamTree.apk` (артефакт `famtree-android`; путь артефакта изменился!). Build-tools берутся самые новые на раннере (там же `d8`, `zipalign`, `apksigner`).
- Риски CI: ключи `name`/`launch_mode`/`has_code` в метаданных `cargo-apk` (если «unknown field» — смотреть README `cargo-apk`/`ndk-build::Activity`); `d8` не принимает путь/ключи; `zipalign`/`apksigner` не найдены. Риски на телефоне: `ClassNotFoundException` для `FamActivity` (имя в манифесте ≠ пакет в `.java`); падение сразу при старте (проверить `adb logcat`); кнопка «Открыть» не открывает пикер.
- Проверить на телефоне: (1) запуск с иконки — кнопка «Открыть»/«Open»; (2) нажать — системный выбор файла, выбрать `.famtree` — «Файл / Людей в дереве»; (3) выбрать не-`.famtree` — красная ошибка; (4) приложение открыто → в файловом менеджере открыть другой `.famtree` «с помощью» FamTree — подхватывается без перезапуска; (5) всё из A3a по-прежнему работает.

## Заметки по A4 (для следующей сессии)
- Android-крейт теперь подключает через `#[path]` ещё: `countries, flags, layout, platform, theme, view` (+ зависимость `image` в `android/Cargo.toml`). `platform.rs` нужен только потому, что на него ссылается `theme.rs` (`system_font`); на Android путь шрифта не существует, и egui берёт встроенные шрифты.
- `lib.rs`: раскладка (`layout::compute`, `LayoutConfig::default()` — **те же числа, что на ПК**) считается в фоновом потоке загрузки, `Loaded` хранит `tree, store, layout, cfg`. `App` держит `ViewState` и `selected`. Если поток загрузки упал (panic) — показывается ошибка, а не вечный спиннер. Экран «Ready»: верхняя панель (кнопки «Открыть», «По размеру», имя выбранного) + `ViewState::show` на всю остальную область. Новых строк интерфейса нет (всё уже было в `TABLE`).
- Правки **десктопного** `src/view.rs` (поведение на ПК не меняется, но файл теперь не «чистый»):
  1. `MAX_TEXTURES`: 150 на Android, 300 на ПК; кэш очищается в начале кадра (раньше — посреди кадра, из-за чего уже нарисованные в этом кадре текстуры могли освободиться).
  2. Два пальца (`multi_touch`): сдвиг по `translation_delta` + масштаб вокруг `start_pos` жеста. Раньше щипок шёл вокруг одного пальца и одновременно тянул схему первым пальцем. Мышь/тачпад ПК идут по старой ветке.
  3. Тап: точка клика берётся из `response.interact_pointer_pos()` (на сенсорном экране `hover_pos` после отпускания пуст, и тап по карточке не срабатывал бы). На ПК результат тот же.
  4. Миниатюры кадра грузятся одним вызовом `MediaStore::get_many` (архив открывается 1 раз за кадр вместо до 6) — это ответ на риск 4. Фото появляется на кадр позже (заглушка → фото). `MediaStore` не менялся: кэшировать `ZipArchive` в нём нельзя, на Windows открытый файл мешает атомарной замене при сохранении.
- Правка десктопного `src/layout.rs`: только тесты (`print_layout_fingerprints`). Новый workflow `.github/workflows/layout-arch.yml`: запускает его на `ubuntu-latest` (x86_64) и `ubuntu-24.04-arm`, job `compare` делает `diff` отпечатков. Если упадёт `diff` — в раскладке есть платформенно-зависимые числа (искать `powf/exp/sin/cos`, `mul_add`, суммирование в другом порядке). Если упадёт сама сборка на Linux (системные библиотеки для eframe) — поставить пакеты через `apt` в шаге перед тестом.
- `android.yml` теперь запускается и при правках `src/**` (общие файлы входят в APK).
- Риски CI: пути `#[path]` для новых модулей; `image` без лишних фич; в `view.rs` на Android `egui::Image::paint_at` без загрузчиков (для `TextureId` не нужны); `MultiTouchInfo` в egui 0.29 (поля `translation_delta`, `zoom_delta`, `start_pos` сверены с исходниками 0.29.1).
- Проверить на телефоне: (1) открыть файл — схема на весь экран, как на ПК (карточки, флаги, полосы пола, линии); (2) щипок двумя пальцами и сдвиг одним пальцем — плавно, без прыжков; (3) тап по карточке — рамка и имя в верхней панели; после перетаскивания тап не срабатывает; (4) «По размеру» возвращает общий вид; (5) фото появляются при приближении; (6) большой файл — нет подвисаний и вылетов по памяти.
- Известные ограничения A4: тап пока не открывает окно человека (A5); верхний отступ 42 px временный (A7); язык интерфейса и тема пока по умолчанию (A7); ресайз/поворот экрана не перевписывает схему автоматически (кнопка «По размеру»).
