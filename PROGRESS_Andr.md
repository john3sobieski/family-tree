## Цель
Приложение для Android, которое **только показывает** семейное дерево из файла `.famtree` — то же, что режим «Просмотр» на ПК. Размещение карточек, линий, флагов и полос пола — **точь-в-точь как на ПК**.

## Что делаем / что НЕ делаем
- Делаем: открыть `.famtree`, схема с pan/pinch-zoom, «По размеру», поиск с перелётом камеры и подсветкой, большое окно человека (фото, данные, переход по родителям/партнёрам/детям), светлая и тёмная тема, 7 языков интерфейса.
- НЕ делаем: редактор, режим «Список», экспорт PNG/PDF, сохранение и автосохранение (файл **никогда не пишется**), ассоциация расширения, установщик, своя шапка окна (`chrome.rs`).

## Решения
Все решения подтверждены пользователем (сессия A2).
- **Архитектура: общее ядро на Rust + egui на Android** (вариант (а) из п. 20 основного PROGRESS). Причина: «точь-в-точь» проще и надёжнее всего получить, если запускать **тот же** код. `layout.rs` (2121 строка, самая сложная часть, вся логика «песочных часов» и шин) зависит только от `model.rs`; `view.rs` + `flags.rs` (флаги рисуются кодом, 197 штук) + `theme.rs` рисуют карточки. Порт на Kotlin/Compose = переписать ~4500 строк и потом вечно синхронизировать две раскладки.
  - Альтернатива (б): Kotlin/Compose, раскладку тянуть через JNI из того же `layout.rs`, а карточки и флаги переписать. Выбирать, только если egui на Android окажется неудобным (клавиатура, жесты) — см. риски.
- **Как подключить код:** отдельный крейт `android/` (cdylib), который подключает файлы десктопа через `#[path = "../src/….rs"] mod …;` (`model, container, media, layout, flags, countries, i18n, theme, view, person_window, search`). Десктоп не трогаем. Если окажется, что модули тянут друг друга (`view` → `app` и т. п.), — разделять на `famtree-core` (lib) + два бинарника, это уже правка десктопа (записать в журнал).
- **Сборка:** GitHub Actions (`ubuntu-latest`, `cargo-ndk` или `cargo-apk`/`xbuild` — выбрать на шаге 1), артефакт — `.apk` (debug, потом подписанный release в GitHub Releases). minSdk 29 (Android 10, выбор пользователя), цели `arm64-v8a` (+ `x86_64` для эмулятора по желанию).
- **Как файл попадает на телефон:** системный выбор файла (Storage Access Framework, `ACTION_OPEN_DOCUMENT`) + открытие `.famtree` из файлового менеджера/«Поделиться». SAF отдаёт `content://`, а не путь → файл копируется в кеш приложения, дальше читается как обычный путь через `container::load`. Последний открытый файл запоминается.
- Формат файла не меняем (`FORMAT_VERSION` = 1), старые и новые `.famtree` читаются.

## Риски (проверить в первую очередь)
1. **Детерминизм раскладки.** В `layout.rs` много `HashMap`/`HashSet`; если где-то порядок обхода влияет на результат, на телефоне схема может отличаться от ПК (и даже от запуска к запуску). Нужен golden-тест: координаты `compute()` для тестовых деревьев (`demo.rs`) сравнивать с эталоном; при расхождении заменять на `BTreeMap`/сортировку.
2. **Экранная клавиатура для поиска** в egui 0.29 на Android: может не открываться сама — тогда вызывать через JNI (`InputMethodManager`) или тонкий Kotlin-слой.
3. **Жесты:** pinch-zoom и pan из egui (`multi_touch`) — проверить плавность на большом дереве; клик по карточке не должен срабатывать после перетаскивания.
4. **Память:** кэш текстур на ПК ≤300 миниатюр, на телефоне, скорее всего, нужно ~100 (проверить). `MediaStore::get` открывает архив на каждую миниатюру — на телефоне заметнее, кэшировать `ZipArchive`.
5. **Шрифты:** Segoe UI нет; нужны кириллица/латиница (встроенные шрифты egui) и CJK для китайского (`/system/fonts/NotoSansCJK*`, путь проверить).
6. **Язык интерфейса:** `i18n::detect_system` на не-Windows читает `LANG` — на Android пусто. Определять через JNI (`Locale`) или `ndk`-конфигурацию.
7. **Окно человека** (`egui::Window`) на телефоне неудобно — делать во весь экран с кнопкой «Назад».
8. Системная кнопка/жест «Назад»: закрывать окно человека, потом выходить.
